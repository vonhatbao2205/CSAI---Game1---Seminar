Game evaluation

Game evaluation tính value của hai policy cố định

$$V^{\pi,\mu}(s)=\mathbb E\left[U(s_T)\mid s,\pi,\mu\right]$$
  • Agent chơi theo π, đối thủ chơi theo μ trong suốt phép đánh giá.
  • Expected utility là trung bình utility, có trọng số theo xác suất.
  • Một ván cụ thể có thể cho kết quả khác expected utility.
Agent chơi theo π, đối thủ chơi theo μ, và cả hai đã cố định.
Evaluation ở đây nghĩa là đo. Thuật toán chưa tìm policy mới.
Kết quả là trung bình theo xác suất; một ván thật có thể ra số khác.

CS221, trang 25-28. Game evaluation tính V^{π,μ}(s) cho một cặp policy đã cố định.

Game evaluation · recurrence

Tại mỗi node, lấy trung bình value theo policy

$$V^{\pi,\mu}(s)=\begin{cases}Utility(s), & IsEnd(s)\\[1mm] \displaystyle\sum_{a}\pi(a\mid s)\,V^{\pi,\mu}(Succ(s,a)), & Player(s)=\text{agent}\\[3mm] \displaystyle\sum_{a}\mu(a\mid s)\,V^{\pi,\mu}(Succ(s,a)), & Player(s)=\text{opp}\end{cases}$$

Recurrence này không có max hay min vì cả hai policy đã cố định.

$$q\,v_1+(1-q)\,v_2$$

Dùng value của subtree thay cho utility, vì một action chưa chắc kết thúc ván.

Tại terminal state, value bằng utility. Tại node khác, lấy trung bình value các con.
Hai con có value v₁, v₂ và xác suất q, 1 − q thì value là q·v₁ + (1 − q)·v₂.
Lượt agent và lượt đối thủ tính giống nhau, chỉ khác bảng xác suất.

CS221, trang 27-28. Mỗi action xảy ra với xác suất cho trước, nên value của node là trung bình value của các nhánh. Chỉ tại terminal state mới dùng utility trực tiếp.

Video manim: từ utility ở leaf, mỗi hộp lấy trung bình và được 0, 2, 5. Root lấy trung bình theo policy agent chọn A: 1·0 + 0·2 + 0·5 = 0. Sau đó policy agent đổi sang chọn đều ba hộp: (0 + 2 + 5)/3 = 7/3.

C có value cao hơn, nhưng Game evaluation vẫn trả 0 vì đang đánh giá policy chọn A. Đổi policy thì value đổi; phép đánh giá không tự tìm policy mới (CS221, trang 25).

Game evaluation · tương tác

Đổi policy thì value ở root đổi theo

Agent luôn chọn A, đối thủ chọn đều, nên root bằng 0. Độ dày edge thể hiện xác suất.
Agent chọn đều ba hộp thì root bằng (0 + 2 + 5)/3 = 7/3. Kéo thanh trượt để đổi μ.

Thanh trượt q là xác suất đối thủ chọn số nhỏ, dùng chung cho cả ba hộp: V(A) = 50 − 100q, V(B) = 3 − 2q, V(C) = 15 − 20q. Mọi node đều tính bằng tổng có trọng số.

Game evaluation · simulation

Tính chính xác bằng recurrence hoặc ước lượng bằng simulation

Simulation cho hai policy chơi nhiều ván rồi lấy trung bình utility.
Mỗi ván chọn A chỉ ra −50 hoặc 50, nên trung bình của vài ván dao động mạnh.
Trung bình mẫu dao động quanh 0 và hội tụ về 0 khi số ván tăng.

Trung bình mẫu V̂ₙ = (1/n) Σ U(s_T⁽ⁱ⁾). Recurrence trên cây hữu hạn cho expected utility chính xác; simulation lấy mẫu action theo hai policy, chơi tới terminal state rồi lấy trung bình. Với số ván hữu hạn, trung bình mẫu có thể khác 0.

Game evaluation · ứng dụng

Game evaluation dùng vào việc gì?

So sánh policy

Giữ policy của agent và đổi đối thủ, hoặc giữ đối thủ và đổi policy của agent.

Policy evaluation

Trong MDP, tính value của một policy cho trước gọi là policy evaluation.

Evaluation function

Là hàm ước lượng value khi chưa search tới terminal state. Phần này thuộc Games 2.
